Чат-бот с Retrieval-Augmented Generation (RAG) на основе LangChain, FastAPI и полностью локальной LLM через **Ollama**.  
Система позволяет загружать документы (PDF, TXT, MD), индексировать их и отвечать на вопросы, используя гибридный поиск (BM25 + FAISS) и генерацию на основе модели **Qwen3-8B** (или другой, загруженной в Ollama).  
Всё работает без внешних API-ключей и интернета — полностью локально.

## Описание задачи

Разработать RAG-сервис, который:

- Принимает на вход документы (PDF, TXT, MD) и индексирует их.
- Отвечает на вопросы пользователей на основе содержимого документов с указанием источников.
- Поддерживает диалоговые сессии с историей (до 20 сообщений).
- Обеспечивает потоковую выдачу ответов (Server‑Sent Events).
- Работает **полностью локально** без использования облачных API.

---

## Принятый подход

### 1. Выбор LLM

В качестве генеративной модели используется **Ollama** с моделью **Qwen3-8B** (GGUF-квантованная версия `Q4_K_M`).  
Причины выбора:

- **Полностью локально** – не требуется интернет, API-ключи или платные подписки.
- **Доступность** – модель `Qwen3-8B` имеет хорошее качество для русского и английского языков, при этом работает на CPU (8 ГБ ОЗУ) или GPU.
- **Удобство** – Ollama предоставляет единый интерфейс для загрузки и запуска моделей, поддерживает `langchain-ollama`.
- **Гибкость** – легко сменить модель, просто изменив `model_name` в `.env`.

Альтернативно рассматривались:
- **OpenAI API** – высокое качество, но требует интернета и платы.
- **Hugging Face Transformers** – тоже локально, но сложнее в настройке (токенизаторы, пайплайны) и медленнее на CPU по сравнению с GGUF через Ollama.

### 2. Эмбеддинг-модель

Используется `sentence-transformers/all-MiniLM-L6-v2` – компактная модель (80 МБ), хорошо работает на CPU и даёт приемлемое качество для русского языка.

### 3. Гибридный поиск (Retriever)

Комбинация двух методов для максимальной точности:
- **BM25** (лексический, вес 0.3) – хорошо находит точные совпадения ключевых слов.
- **FAISS + MMR** (семантический, вес 0.7) – находит смысловые аналоги, диверсифицируя результаты.

Это позволяет покрыть как точные термины, так и синонимы / перефразировки.

### 4. Промпт-инжиниринг

Системный промпт явно запрещает модели выдумывать факты и предписывает отвечать только на основе предоставленного контекста. При отсутствии информации возвращается стандартный ответ: *«В базе знаний нет информации по этому вопросу»*.

### 5. Управление сессиями

- Каждая сессия идентифицируется по `session_id`.
- История хранится в памяти сервера (для простоты) с автоматическим удалением неактивных сессий через TTL (по умолчанию 1 час).
- Максимальное количество сообщений в истории – 20 (настраивается).

### 6. Обработка ошибок и валидация

- Входные данные валидируются через Pydantic-схемы.
- Таймаут запроса – 60 секунд.
- Если индекс не загружен – возвращается HTTP 503.
- Глобальный обработчик исключений логирует ошибку и возвращает стандартизированный JSON.

## Конфигурация

### app/config.py (изменения)

```python
from pydantic_settings import BaseSettings
from functools import lru_cache

class Settings(BaseSettings):
    # Ollama LLM
    model_name: str = "hf.co/Qwen/Qwen3-8B-GGUF:Q4_K_M"  # или любая другая модель в Ollama

    # LangSmith (опционально)
    langchain_tracing_v2: bool = False
    langchain_api_key: str = ""
    langchain_project: str = "rag-chatbot"

    # RAG
    chunk_size: int = 1000
    chunk_overlap: int = 200
    retriever_k: int = 4
    index_path: str = "indexes/faiss_index"

    # Сессии
    max_history_messages: int = 20
    session_ttl_seconds: int = 3600

    # API
    max_tokens: int = 2000
    request_timeout: int = 60

    class Config:
        env_file = ".env"
        env_file_encoding = "utf-8"

@lru_cache()
def get_settings() -> Settings:
    return Settings()
```

### .env

```env
MODEL_NAME=hf.co/Qwen/Qwen3-8B-GGUF:Q4_K_M

# LangSmith (опционально)
LANGCHAIN_API_KEY=ls_...
LANGCHAIN_TRACING_V2=true
LANGCHAIN_PROJECT=rag-chatbot-prod
```

### app/services/rag.py (фрагмент)

```python
from langchain_ollama import ChatOllama

class RAGService:
    def __init__(self, settings: Settings):
        self.settings = settings
        self.model = ChatOllama(
            model=settings.model_name,
            num_ctx=settings.max_tokens,
            temperature=0
        )
        # ... остальное без изменений
```

## Установка и запуск

### Требования

- **Python 3.9+**
- **Ollama** – установлен и запущен
- **Модель** – скачана через Ollama (см. ниже)
- **8 ГБ ОЗУ** (рекомендуется для CPU-инференса модели 8B)

---

### 1. Установка Ollama и загрузка модели

**Linux / macOS / Windows (WSL2):**

```bash
# Установить Ollama (инструкции на https://ollama.com)
curl -fsSL https://ollama.com/install.sh | sh   # Linux/macOS

# Запустить сервер Ollama (если ещё не запущен)
ollama serve

# Скачать модель Qwen3-8B (GGUF) – может занять несколько минут
ollama pull hf.co/Qwen/Qwen3-8B-GGUF:Q4_K_M

# Проверить, что модель доступна
ollama list
```

---

### 2. Клонирование репозитория

```bash
git clone https://github.com/popyaske/rag_chatbot_api.git
cd rag_chatbot
```

---

### 3. Создание и активация виртуального окружения

**Linux / macOS:**
```bash
python3 -m venv venv
source venv/bin/activate
```

**Windows:**
```bash
python -m venv venv
venv\Scripts\activate
```

---

### 4. Установка Python-зависимостей

```bash
pip install -r requirements.txt
```

---

### 5. Настройка переменных окружения

Создайте `.env` в корне проекта и заполните по примеру выше (обязательно укажите `MODEL_NAME`).

---

### 6. Запуск сервера FastAPI

**Убедитесь, что Ollama запущен** (`ollama serve` работает в фоне).

```bash
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

При первом запуске будет загружен FAISS-индекс (если он существует) и модель Ollama (она уже загружена в память).

---

### 7. Проверка работоспособности

```bash
curl http://localhost:8000/health
```

Должен вернуться JSON:
```json
{"status":"ok","index_loaded":false,"active_sessions":0,"timestamp":"..."}
```

> **Примечание:** Индекс будет загружен только после загрузки хотя бы одного документа через `/documents/upload`.

## API Эндпоинты

### Чат-эндпоинты (`/chat`)

| Метод | Эндпоинт | Описание |
|-------|----------|----------|
| POST | `/chat/` | Обычный (не стриминговый) запрос |
| GET | `/chat/stream` | Стриминговый запрос через SSE |
| DELETE | `/chat/{session_id}` | Очистка истории сессии |

#### POST /chat/
**Запрос:**
```json
{
  "session_id": "user_1",
  "question": "Как работает asyncio.gather?"
}
```

**Ответ:**
```json
{
  "session_id": "user_1",
  "answer": "asyncio.gather() запускает несколько корутин параллельно...",
  "sources": ["asyncio_guide.txt"],
  "tokens_used": 0,
  "latency_ms": 523.4
}
```

#### GET /chat/stream
**Параметры URL:**
- `session_id` (string)
- `question` (string)

**Ответ:** Server-Sent Events
```json
data: {"type": "sources", "sources": ["doc1.pdf"]}
data: {"type": "token", "content": "asyncio"}
data: {"type": "token", "content": ".gather()"}
data: {"type": "done", "full_answer": "asyncio.gather()..."}
```

### Документы (`/documents`)

| Метод | Эндпоинт | Описание |
|-------|----------|----------|
| POST | `/documents/upload` | Загрузка документа в индекс |
| GET | `/documents/stats` | Статистика индекса |

#### POST /documents/upload
**Формат:** `multipart/form-data` с полем `file` (.pdf, .txt, .md)

**Ответ:**
```json
{
  "message": "Файл 'asyncio_guide.pdf' проиндексирован",
  "chunks_indexed": 45,
  "index_size": 245
}
```

### Health Check

| Метод | Эндпоинт | Описание |
|-------|----------|----------|
| GET | `/health` | Проверка состояния |

  -H "Content-Type: multipart/form-data" \

## Допущения и компромиссы

### Допущения
- Документы в основном на русском языке (но поддерживаются и другие).
- Индекс хранится локально и загружается при старте.
- Сессии хранятся в памяти сервера (для простоты; в продакшене рекомендуется Redis).
- Модель уже скачана в Ollama и доступна.

### Компромиссы
- **Скорость vs качество** – модель 8B даёт хорошее качество, но медленнее, чем 3B. Для CPU-инференса можно уменьшить `num_ctx` или выбрать модель поменьше.
- **Память vs функциональность** – хранение сессий в памяти упрощает код, но не масштабируется.
- **Точность vs сложность** – гибридный поиск сложнее, но даёт лучшие результаты.

## Анализ ошибок и возможные улучшения

### Наблюдаемые проблемы
1. **Загрузка модели в Ollama может занять время** при первом запросе.  
   → **Решение:** прогреть модель предварительным запросом (healthcheck).
2. **Иногда ответ содержит «галлюцинации»** (редко, т.к. промпт строг).  
   → **Решение:** усилить системный промпт или добавить поствалидацию.
3. **Потеря источников при чанкировании** – метаданные могут не сохраниться.  
   → **Решение:** явно добавлять `source` в каждый чанк.
4. **Медленная индексация больших PDF** – может длиться > 30 секунд.  
   → **Решение:** вынести индексацию в фоновые задачи (Celery).

### Рекомендации по улучшению
- **Кэширование повторяющихся вопросов** – через Redis.
- **Аутентификация** – добавить JWT для защиты эндпоинтов.
- **Веб-интерфейс** – простой фронтенд для демонстрации.
- **Поддержка большего числа форматов** (DOCX, HTML, JSON).
- **Асинхронная загрузка документов** – не блокировать основной поток.

## Производительность (ориентировочно)

| Операция | Время (на CPU, 8 ядер) |
|----------|------------------------|
| Загрузка индекса (1000 чанков) | < 1 сек |
| Инференс Ollama (одно сообщение) | 2–5 сек |
| Стриминг (по токенам) | 0.5–2 сек |
| Индексация документа (10 стр.) | 3–6 сек |
| Запрос гибридного поиска | < 0.1 сек |

## Известные ограничения

- Работает только с локально установленным Ollama.
- Сессии не сохраняются между перезапусками сервера.
- Нет поддержки изображений или таблиц (только текст).
- Ограниченное число поддерживаемых форматов файлов.

---

## Архитектурные решения

- **Dependency Injection** через `dependencies.py` – облегчает тестирование.
- **Lifespan** для инициализации сервисов при старте.
- **Гибридный ретривер** – повышает точность поиска.
- **SSE** для стриминга – эффективнее WebSocket в данном сценарии.
